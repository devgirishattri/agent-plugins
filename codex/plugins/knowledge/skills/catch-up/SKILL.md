# Catch up

Use the time or message the user names. Otherwise start at their last
substantive request before the catch-up. A tool notification or a peer reply
does not move that starting point. If the earlier conversation is unavailable,
identify the earliest point you can substantiate.

Summarize the changes that matter to the user. Distinguish observed results,
reports from others, and work still open. Cite a check or artifact when it
helps the user judge a result. When the user names a scheduler task, use its
most recent status output or report already in this conversation. Attribute
the state and say when it was observed. If the conversation contains no
record, say the current state is unknown. The normal status helper can
initialize or migrate the ledger. If the user also asks for a fresh lookup,
use the scheduler's status workflow for that request and include its result.

List only decisions the user actually needs to make, with the options and
consequence when known. When there are none, say so. If the interval has no
changes, a sentence is enough. Keep this in the current conversation. Saving
a snapshot, sending a message and scanning other sessions are separate
operations.
